# Homework Assignment: PostgreSQL — Intermediate SQL

**Teacher:** Evan Flint
**Related notes:** [Training 4](/training-notes-site/notes/training-4/) (CI/CD for Data Eng. / Databases & SQL Providers)

## Objective

Use the existing `sample_database` and the imported warehouse tables:

`customers`, `employees`, `offices`, `orders`, `orderdetails`, `payments`, and `products`.

For each question, write the SQL necessary to produce the requested result. Do not modify the source data unless the question specifically asks you to create an index.

**Submission:** Put all 10 answers in a single `.sql` file, numbered with SQL comments such as `-- Question 1`. All queries should execute successfully against the existing sample database.

## Questions

### 1. Subquery — Above-Average Prices
Find all records in `orderdetails` whose `price` is greater than the average price across the entire `orderdetails` table. Return `order_number`, `product_number`, `product_category`, and `price`. Solve this using a subquery.

### 2. CTE — Order Totals
Create a CTE named `order_totals` that calculates the total value of each order using:
```
price × quantity
```
Return only orders whose total value is greater than 5,000, sorted from highest total to lowest.

### 3. CTE + Join — Product Revenue
Create a CTE that calculates the total revenue generated by each `product_number` from `orderdetails`. Then join the CTE to `products` so the final result contains `product_number`, `product_name`, `product_category`, and total revenue. Sort from highest revenue to lowest.

### 4. Window Function — Category Average
For every record in `orderdetails`, return `product_number`, `product_category`, and `price`, along with the average price for that product's category. Use `AVG()` as a window function with `PARTITION BY`. Do not use `GROUP BY`.

### 5. Window Function — Ranking
Rank the products within each `product_category` according to `price`, with the highest price ranked first. Return `product_number`, `product_category`, `price`, and the rank. Use `DENSE_RANK()` so products with identical prices receive the same rank.

### 6. CTE + Window Function — Top 3 per Category
Find the three highest-priced records in each product category. Use a window function to assign the ranking and a CTE to allow you to filter the results. The final result should contain only ranks 1–3.

### 7. Window Function — Previous Payment
Sort payments chronologically by `payment_date`. For each payment, display `payment_id`, `payment_date`, `amount`, and the amount of the previous payment. Use `LAG()`. Add another calculated column showing:
```
current payment amount - previous payment amount
```

### 8. Conditional Aggregation
Produce one row containing:
- total number of payments
- total value of all payments
- number of payments of at least 1,000
- total value of payments of at least 1,000

Use `CASE` inside aggregate functions for the last two calculations.

### 9. Index + Query Plan
Investigate this query:
```sql
SELECT *
FROM orderdetails
WHERE product_category = 'Classic Cars';
```
First run it with `EXPLAIN ANALYZE` and record the execution plan. Then create an index on `product_category` and run the same `EXPLAIN ANALYZE` again.

Answer in comments in your SQL file:
```sql
-- What type of scan was used before the index?
-- What type of scan was used afterward?
-- Did PostgreSQL actually choose to use your index?
-- Why might PostgreSQL choose a sequential scan even though an index exists?
```

### 10. Capstone — Top Products by Revenue
Write one query that determines the three highest-revenue products within each product category.

Revenue for a line item is:
```
price * quantity
```

Your final output must contain: `product_category`, `product_number`, `product_name`, `total_revenue`, `category_rank`.

**Requirements:**
- Join `orderdetails` with `products`
- Aggregate the individual order lines to calculate total revenue per product
- Use at least one CTE
- Use a window function to rank products within their categories
- Return only the top three ranks from each category
- Sort the final output by category and then rank

## Answers

```sql
-- PostgreSQL Homework — Intermediate SQL
-- Alexander Jackson

-- Question 1
-- Subquery — Above-Average Prices
SELECT order_number, product_number, product_category, price
FROM orderdetails
WHERE price > (
    SELECT AVG(price)
    FROM orderdetails
);

-- Question 2
-- CTE — Order Totals
WITH order_totals AS (
    SELECT
        order_number,
        SUM(price * quantity) AS total_value
    FROM orderdetails
    GROUP BY order_number
)
SELECT order_number, total_value
FROM order_totals
WHERE total_value > 5000
ORDER BY total_value DESC;

-- Question 3
-- CTE + Join — Product Revenue
WITH total_revenue AS (
    SELECT product_number,
        SUM(price * quantity) AS total
    FROM orderdetails
    GROUP BY product_number
)
SELECT
    x.product_number,
    y.product_name,
    y.product_category,
    x.total
FROM total_revenue x
JOIN products y ON x.product_number = y.product_number
ORDER BY x.total DESC;

-- Question 4
-- Window Function — Category Average
SELECT
    product_number,
    product_category,
    price,
    AVG(price) OVER (PARTITION BY product_category) AS category_average
FROM orderdetails;

-- Question 5
-- Window Function — Ranking
WITH ranked_products AS (
    SELECT
        product_number,
        product_category,
        price,
        DENSE_RANK() OVER (PARTITION BY product_category ORDER BY price DESC) AS price_rank
    FROM orderdetails
)
SELECT *
FROM ranked_products;

-- Question 6
-- CTE + Window Function — Top 3 per Category
WITH ranked_products AS (
    SELECT
        product_number,
        product_category,
        price,
        DENSE_RANK() OVER (PARTITION BY product_category ORDER BY price DESC) AS price_rank
    FROM orderdetails
)
SELECT *
FROM ranked_products
WHERE price_rank <= 3
ORDER BY product_category, price_rank;

-- Question 7
-- Window Function — Previous Payment
SELECT
    payment_id,
    payment_date,
    amount,
    LAG(amount) OVER (ORDER BY payment_date) AS previous_amount,
    amount - LAG(amount) OVER (ORDER BY payment_date) AS amount_change
FROM payments
ORDER BY payment_date;

-- Question 8
-- Conditional Aggregation
SELECT
    COUNT(*) AS total_payments,
    SUM(amount) AS total_value,
    SUM(CASE WHEN amount >= 1000 THEN 1 ELSE 0 END) AS payments_over_1000,
    SUM(CASE WHEN amount >= 1000 THEN amount ELSE 0 END) AS value_over_1000
FROM payments;

-- Question 9
-- Index + Query Plan
EXPLAIN ANALYZE
SELECT *
FROM orderdetails
WHERE product_category = 'Classic Cars';

CREATE INDEX idx_orderdetails_product_category
ON orderdetails(product_category);

EXPLAIN ANALYZE
SELECT *
FROM orderdetails
WHERE product_category = 'Classic Cars';

-- What type of scan was used before the index?
-- Seq Scan on orderdetails (full table scan, filtering out non-matching rows).
--
-- What type of scan was used afterward?
-- Index Scan using idx_orderdetails_product_category.
--
-- Did PostgreSQL actually choose to use your index?
-- Yes - confirmed by "Index Scan using idx_orderdetails_product_category on orderdetails" in the second EXPLAIN ANALYZE output.
--
-- Why might PostgreSQL choose a sequential scan even though an index exists?
-- The query planner is cost-based, not rule-based - it estimates the cost of each available plan and
-- picks whichever is cheaper. On a small table, or when a filter matches a large fraction of rows,
-- reading the whole table sequentially can be cheaper than the overhead of traversing the index
-- structure plus a separate lookup for each matching row. The planner only switches to an Index Scan
-- when it estimates that skipping enough non-matching rows makes the index traversal worth it.

-- Question 10
-- Capstone — Top Products by Revenue
WITH product_revenue AS (
    SELECT
        od.product_number,
        SUM(od.price * od.quantity) AS total_revenue
    FROM orderdetails od
    GROUP BY od.product_number
),
ranked_revenue AS (
    SELECT
        p.product_category,
        pr.product_number,
        p.product_name,
        pr.total_revenue,
        DENSE_RANK() OVER (PARTITION BY p.product_category ORDER BY pr.total_revenue DESC) AS category_rank
    FROM product_revenue pr
    JOIN products p ON pr.product_number = p.product_number
)
SELECT *
FROM ranked_revenue
WHERE category_rank <= 3
ORDER BY product_category, category_rank;
```
